# SQL Server → Amazon Redshift — Conversion Rules

Rules for converting SQL Server objects (tables, views, set-based procedures, functions, ETL SQL)
to Amazon Redshift (RA3 / Serverless, current SQL surface as of 2026). They complement
`governance.md` (contracts, placement) and reuse the SQL-dialect knowledge of `migration.md`
where Redshift and PostgreSQL agree. Implemented by `.kiro/skills/sql-conversion-redshift/SKILL.md`;
corner cases `RS-nn` in that skill's `references/corner-cases.md`. Rule ids `[R-n]`.

Redshift is an analytical warehouse, not an OLTP engine: **BI edge views, curated analytical
tables and set-based loads belong here; row-by-row procedural logic does not** (placement
decided by `migration-assessment`).

## Hard rules

1. **[R-1] Convert only what Redshift can host.** Triggers, table-valued functions, table
   variables, sequences, `CHECK` constraints, `FOR XML/JSON`, CLR, linked servers, `INSTEAD OF`
   logic and nested cursors have no Redshift equivalent: flag them with
   `-- TODO: MANUAL REVIEW REQUIRED — …`, status `PARTIAL`, and route the object elsewhere
   (Aurora PostgreSQL for procedural logic) rather than emulating them [RS-01…RS-06].
2. **[R-2] Keep what Redshift keeps.** `GETDATE()`, `DATEADD(part, n, ts)`, `DATEDIFF(part, a, b)`,
   `CHARINDEX`, `LEN`, `TOP n`, `CONVERT(type, expr)`, `DATEPART`, `#temp` tables are valid
   Redshift SQL: do not rewrite them for their own sake (the ledger records "kept") [RS-10].
3. **[R-3] Replace what Redshift lacks:** `ISNULL(a,b)` → `NVL(a,b)`/`COALESCE`; `IIF(c,a,b)` →
   `CASE WHEN c THEN a ELSE b END` (or `DECODE`); `STRING_AGG(x, ',') WITHIN GROUP (ORDER BY …)`
   → `LISTAGG(x, ',') WITHIN GROUP (ORDER BY …)`; `'a' + b` → `'a' || b`; `NEWID()` → no
   equivalent (generate the key upstream or use `MD5`/identity); `OBJECT_ID`, `@@ROWCOUNT` →
   `GET DIAGNOSTICS`/`ROW_COUNT` inside procedures only [RS-11…RS-16].
4. **[R-4] Identifiers.** `[Bracketed]` → unquoted snake_case (Redshift folds to lower case;
   quoted mixed case needs `enable_case_sensitive_identifier`); the consumer contract decides
   output column names and order [RS-17].
5. **[R-5] Types.** `NVARCHAR(n)`/`VARCHAR(n)` → `VARCHAR(n)` sized in **bytes** (multiply by up
   to 4 for non-Latin text); `NVARCHAR(MAX)`/`TEXT` → `VARCHAR(65535)` (a bare `TEXT` silently
   becomes `VARCHAR(256)`); `NCHAR`/`CHAR` → `CHAR` (single-byte only); `MONEY` → `DECIMAL(19,4)`;
   `BIT` → `BOOLEAN`; `UNIQUEIDENTIFIER` → `VARCHAR(36)`; `DATETIME` → `TIMESTAMP` (SQL Server's
   1/300 s rounding is lost); `DATETIMEOFFSET` → `TIMESTAMPTZ`; `VARBINARY` → `VARBYTE`;
   `XML`/`JSON text` → `SUPER` or `VARCHAR`; `GEOGRAPHY` → `GEOMETRY`/`GEOGRAPHY` only after a
   spatial decision; `DECIMAL` precision ≤ 38 [RS-20…RS-27].
6. **[R-6] Tables are designed, not copied.** Emit `DISTSTYLE AUTO` and `SORTKEY AUTO` unless a
   design decision (join key, filter column, small dimension → `DISTSTYLE ALL`) is supplied;
   never invent a distribution key from column names alone. Clustered/non-clustered indexes
   become sort-key candidates recorded in the ledger, not indexes [RS-30, RS-31].
7. **[R-7] Constraints are informational.** PK/UNIQUE/FK are kept for the optimizer but not
   enforced; `NOT NULL` is enforced; `CHECK` is dropped with a ledger row; uniqueness must be
   proven by a validation query (`V-014`) [RS-32].
8. **[R-8] Identity is not a sequence.** `IDENTITY(seed, step)` values are unique but not
   contiguous and not in load order; `GENERATED BY DEFAULT AS IDENTITY` allows explicit values
   but does not check uniqueness; never depend on gap-free keys [RS-33].
9. **[R-9] Procedures are PL/pgSQL with Redshift limits:** `CREATE OR REPLACE PROCEDURE … LANGUAGE
   plpgsql`, called with `CALL`; results are returned through an `INOUT refcursor` or a temp
   table; `OUT` args must be `INOUT` when nested; `COMMIT`/`ROLLBACK` are allowed only when the
   procedure is not called inside a transaction block; `NONATOMIC` mode when statements must
   commit individually; one open cursor per session; exception handling is limited (no
   subtransactions); dynamic SQL through `EXECUTE` with `quote_ident`/`quote_literal` [RS-40…RS-46].
10. **[R-10] MERGE.** Redshift `MERGE INTO target USING source ON … WHEN MATCHED THEN UPDATE|DELETE
    WHEN NOT MATCHED THEN INSERT` (one clause each; no `WITH`; source ≠ target; a target row may
    match at most one source row; `REMOVE DUPLICATES` for identical layouts). T-SQL `WHEN NOT
    MATCHED BY SOURCE` and multiple `WHEN MATCHED AND …` branches need a two-statement
    rewrite [RS-50, RS-51].
11. **[R-11] Views.** Edge views over Redshift tables are regular views; views over Spectrum
    external tables or that must survive base-table rebuilds are late-binding
    (`WITH NO SCHEMA BINDING`, every reference schema-qualified, no recursive CTE inside).
    Materialized views only for approved Middle materialization (`AUTO REFRESH` limits) [RS-52, RS-53].
12. **[R-12] Case-insensitive comparisons** from `…_CI_AS` collations are made explicit: a
    `CASE_INSENSITIVE` database/column collation decided at design time, or `LOWER()` on both
    sides; mixing collations in one query fails [RS-60].
13. **[R-13] Security is explicit.** Identity functions and authorization joins become Redshift
    RLS policies (`CREATE RLS POLICY … USING (…)`, `ATTACH RLS POLICY … TO ROLE …`) and masking
    policies (`CREATE MASKING POLICY`) only after the identity mapping is approved; the view keeps
    only presentation logic; superusers bypass RLS [RS-61].
14. **[R-14] Prove it.** Static checks (`redshift_tool.py check`) must be clean; execution
    evidence comes from the Redshift Data API against a database whose name contains
    test/dev/sandbox/local, or the check stays listed as unexecuted (`V-004`) [RS-70].
15. **[R-15] Done means packaged** (process rule): converted SQL, rule ledger, classification and
    validation manifest in the conversion package with hashes and the run id.

## Datatype map (SQL Server → Redshift)

| SQL Server | Redshift | Notes |
|---|---|---|
| `TINYINT`/`SMALLINT`/`INT`/`BIGINT` | `SMALLINT`/`SMALLINT`/`INTEGER`/`BIGINT` | TINYINT 0–255 range check lost |
| `BIT` | `BOOLEAN` | `WHERE flag = 1` → `WHERE flag` |
| `DECIMAL(p,s)`/`NUMERIC(p,s)` | `DECIMAL(p,s)` | p ≤ 38, s ≤ 37 |
| `MONEY`/`SMALLMONEY` | `DECIMAL(19,4)`/`DECIMAL(10,4)` | no money type |
| `FLOAT`/`REAL` | `DOUBLE PRECISION`/`REAL` | |
| `CHAR(n)`/`NCHAR(n)` | `CHAR(n)` | single-byte only; multibyte → `VARCHAR(4n)` |
| `VARCHAR(n)`/`NVARCHAR(n)` | `VARCHAR(n)` bytes | ×4 for multibyte; max 65535 |
| `VARCHAR(MAX)`/`NVARCHAR(MAX)`/`TEXT`/`NTEXT` | `VARCHAR(65535)` | never bare `TEXT` (=256) |
| `DATE`/`TIME`/`DATETIME`/`DATETIME2`/`SMALLDATETIME` | `DATE`/`TIME`/`TIMESTAMP` | microsecond precision |
| `DATETIMEOFFSET` | `TIMESTAMPTZ` | stored in UTC |
| `UNIQUEIDENTIFIER` | `VARCHAR(36)` | no UUID type |
| `VARBINARY`/`BINARY`/`IMAGE` | `VARBYTE(n)` | max 16 MB; not usable in UDFs |
| `XML`, JSON text | `SUPER` (≤ 16 MB) or `VARCHAR` | |
| `GEOGRAPHY`/`GEOMETRY` | `GEOGRAPHY`/`GEOMETRY` | spatial functions differ; decision required |
| `ROWVERSION`, `SQL_VARIANT`, `HIERARCHYID`, `CURSOR`, table types | none | manual review |

## Validation checklist

- [ ] `redshift_tool.py check` reports 0 problems: no residual T-SQL, no unsupported feature,
      no bare `TEXT`, no `CHECK`, no trigger/sequence/table function *(auto)*
- [ ] every table carries an explicit `DISTSTYLE`/`SORTKEY` decision or `AUTO` with a ledger row
- [ ] ledger explains every non-trivial transformation; unsupported constructs are `PARTIAL`
- [ ] execution evidence (`run`) on a test database, or `V-004` listed as unexecuted
- [ ] uniqueness (`V-014`), row counts (`V-012`) and consumer contract (`V-005`) queries generated
